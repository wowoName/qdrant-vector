# 文件解析与向量切片审计

审计日期：2026-10-13。现有数据库抽查最多 3,000 个切片：2,999 个 xlsx 切片和 1 个图片切片，使用本地 bge-small-zh-v1.5 tokenizer 检查，最大分别为 325 和 12 tokens，无超过 512 tokens 的样本。此抽查不是全库普查。本地上传目录没有 PDF，因此 PDF 结论来自代码审计、构造文件回归和实际处理函数验证，不能当作用户真实 PDF 的完整性证明。

## 压缩与内容丢失

入库路径未发现先用 LLM 摘要代替正文的步骤，也未配置向量量化或截断向量维度。向量本身是语义表示，原文另存于 PostgreSQL/Qdrant payload，不能从向量还原原文。

修复前存在的具体问题：

1. PDF 按模拟分页猜测页眉页脚，会删除正文中的重复行及短纯数字行；断行拼接还会把标题、表格及字段连接起来。NFKC 可能改变上标单位。
2. 递归切片普通与流式实现对混合大小段落的顺序不一致；min_size 会过滤短尾段；重叠拼接可能超出 chunk_size。固定切片同样可能丢弃尾段，并忽略显式的零重叠。
3. PDF/Word 默认 800 字符、其他部分类型 600 字符，不能保证符合当前模型的 512 token 上限。旧向量化路径依赖模型默认截断，尾部信息可能没进入向量。
4. Word 表格被解析进 tables，却未加入 text/pages，因此不会进入普通正文切片。
5. 按类型的 min_size 设置写到了不存在的 chunk_min_size 属性；父子块在创建后修改外层参数，未同步内部切片器。
6. CSV record 导入误走 Excel 解析，xls record 流误走 openpyxl。PPT 标题重复、标题页丢失及空幻灯片导致的页码偏移也有问题。

## 已实施的处理规则

| 文件 | 处理与参数 | 保留方式 |
| --- | --- | --- |
| PDF | 按物理页，默认 400 字符、40 字符重叠 | 保留数字、单位及换行；排序提取；检测到的表格补充字段和值关系；扫描页使用 OCR |
| Word | 按正文段落、标题和表格顺序，400/40 | 表格文字进入其所在章节；不再只放在独立 tables 属性里 |
| PPT | 每张幻灯片保留一个页槽，400/40 | 标题、正文、表格、备注；标题不重复，标题页不丢失 |
| Markdown | 保留标题分节，400/40 | 不再清除代码缩进 |
| HTML | 按标题/段落，400/40 | 保留内联词间边界；无段落标签时回退全文提取 |
| TXT | 全局默认 500/50 | 有序分片，不丢弃短尾段 |
| Excel/CSV | 原始数据按记录保留，短记录一个向量，长记录分片 | 不跨患者合并，不跨行重叠；xls/CSV 走各自解析器 |
| 图片/音频 | OCR/ASR 文字按句子切片 | 无有效文字时任务失败，不生成空成功索引 |
| 视频 | 当前为抽帧 OCR/现有音轨处理 | 抽帧不能保证完整覆盖每一帧内容，不能替代完整视频理解 |

字符数只是第一层控制。所有文档入库任务在向量化前都使用当前模型 tokenizer（计入特殊 token）检查，超限内容拆成独立切片，再保存数据库并生成向量。不会通过平均多个向量、摘要或删除尾部来凑长度。标准、chunk 流式、page 流式均使用此保护；切片序号重新连续编号，保留页码、原切片序号和拆分位置。直接调用 embedding 的超限输入会明确失败。

短尾段不以 min_size 为由删除；min_size 只作为选择自然边界的偏好。零重叠生效，所有默认递归切片输出是原始文本的连续窗口，字符位置可核验。

## PDF 的边界与建议

- 扫描页 OCR 默认开启，150 dpi。检测条件为有图片且无可选文字，或文字少于 80 字符且图片覆盖面积超过页面一半。OCR 未安装、执行失败或没有识别到文字时明确报错，不跳过扫描页。这属于启发式检测，不保证发现所有带局部文字的扫描内容。
- PyMuPDF 排序提取改善基本阅读顺序，不能保证复杂双栏、跨栏、脚注及跨页表格的顺序完全正确；这类材料应进一步接入布局解析器，并用真实代表性文件对照页面核验。
- 表格提取在原有文字之外补充结构化表达，避免删正文，代价是可能产生重复文本。没有框线、合并表头或扫描表格的字段关系仍需专门校验。
- 页码保留为 0-based 内部页码；显示给用户时应加一。Word/Markdown/HTML 的 page_num 是章节序号，不是打印页码。
- 不自动去除页眉页脚。若确实需要，可按真实页面几何位置和跨页频率建立可审计规则；不要全局删除重复正文。
- 对章节目较长的 PDF，可以配置父子块：较小的子块检索、父块补充上下文。当前先保留默认递归策略，避免未经召回评测就全面更换策略。
- 图表、公式图片、手写字和纯视觉信息不等于可选文本，文本/OCR 索引不保证完整理解；这类材料需要多模态/公式识别能力。

## 旧数据与验证

代码修复仅影响重新处理或新上传的文件。旧解析已经删除的数字、短尾段、Word 表格，不能靠从旧 chunks 重建向量恢复；必须从原文件重新解析和切片。`rebuild_vectors.py` 在删除现有集合前先校验旧文本的 token 长度，发现超限就中止，避免清空正常索引后才报错。

本次没有批量重建用户所有知识库。默认策略和参数建议以少量真实代表文件做召回评测：检查原文覆盖率、每页切片数、token 分布、表格字段关系，以及数字/药名/尾注的可检索性。

回归测试覆盖短尾段、数字与单位、普通/流式一致性、真实 tokenizer、PDF OCR 失败、PDF 表格、Word 表格顺序、PPT 页槽、CSV record 和 Markdown 缩进。PDF 三条任务路径的保存切片与向量输入长度也直接验证。

Windows 服务验证额外发现：Proactor 下重载的继承监听套接字可报 WinError 87。入口已使用 Windows 单进程、禁用内置热重载。启动请用 `uv run python -m app.main`；修改代码后手动重启。
